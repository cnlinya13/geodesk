# GEODesk

中文 | [English](README.md)

GEODesk 是面向网站运营者、内容团队和 GEO 实践者的 AI 搜索可见性监测、诊断与优化工作台，当前主要面向中文网站。

它将固定问题集、模型原始回答、引用证据、网站检查和优化后的复测放在同一条工作流中，帮助你了解：AI 如何理解和引用网站，哪些问题值得优先改进，以及优化前后的结果是否发生变化。

> 当前版本为本地单用户 MVP，真实模型接入以豆包为主。项目提供无需模型密钥的合成数据演示，但不承诺提升搜索排名、推荐率或引用率。多模型选择、地区化和全球 GEO 监测仍属于路线图。

## 核心工作流

```text
建立项目 → 确定监测问题 → 初始诊断 → 网站检查与优化任务 → 人工实施 → 同口径复测
```

| 阶段 | 当前功能 |
| --- | --- |
| 项目与口径 | 管理网站和优化目标；维护固定 20 题，分为推荐类 10 题、选择类 6 题、决策类 4 题；支持问题锁定。 |
| 初始诊断 | 保存逐题模型回答、引用链接与模型信息；分别计算推荐率和官网引用率；提供诊断报告及 PDF 功能。 |
| 网站检查 | 分开执行不依赖 AI 的技术检查和模型参与的内容检查，保留问题与证据。 |
| 优化任务 | 生成文章优化任务与正文，由使用者实际发布后在工作台人工确认。 |
| 持续监测 | 发起独立监测轮次，在相同问题口径下比较结果。 |
| 状态与数据 | 使用 PostgreSQL 保存业务结果和后台任务状态，支持迁移及任务进度查询。 |

当前没有完整的多用户账号与权限系统，也不提供自动发布、默认定时监测或统一代付模型费用。**请勿将当前 API 直接暴露到公网。**

## 快速体验：无需模型密钥

### 准备环境

- Node.js 24；仓库 `.nvmrc` 指定 24.18.0。
- npm 11 或更高版本。
- 下载或克隆项目后，在 `geodesk` 工程根目录执行以下命令。

```bash
npm ci
npm run demo
```

打开 **http://127.0.0.1:5174**。演示 API 使用 `127.0.0.1:8788`。

演示不需要 PostgreSQL、`.env.local` 或模型 API Key。安装依赖可能需要联网；演示运行本身不请求真实网站或模型。界面使用合成数据，内存数据在服务重启后重置。

可体验的流程：创建项目 → 生成并确认 20 题 → 查看合成诊断和引用 → 生成一条优化任务与正文 → 人工确认发布 → 完成一轮合成复测。

演示不执行真实网站技术检查、内容检查或 PDF 生成；这些操作会禁用或明确返回不支持。它用于理解交互流程，不代表真实模型效果或数据库持久化验收。

在终端按 `Ctrl+C` 停止演示。

## 真实运行：独立数据库与豆包配置

### 1. 安装与配置

除上述 Node.js 和 npm 环境外，需要 PostgreSQL。随仓库提供的 Compose 配置使用 PostgreSQL 16；自行配置数据库时，当前文档要求 PostgreSQL 14 或更高版本。

```bash
npm ci
cp .env.example .env.local
```

编辑 `.env.local`：

- `PGHOST`、`PGPORT`、`PGUSER`、`PGPASSWORD`：独立开发数据库的连接配置。
- `PGDATABASE`：必须为 `geodesk`。
- `DOUBAO_API_KEY`、`DOUBAO_MODEL_ID`、`DOUBAO_API_ENDPOINT`：由使用者提供的豆包服务配置；真实模型操作需要全部配置，endpoint 须符合客户端的 HTTPS 校验。

不要将 `.env.local` 提交到仓库，也不要在浏览器端设置模型密钥。服务端也支持完整的进程环境变量，不强制要求该文件存在。

### 2. 启动独立 PostgreSQL

如果使用 Docker Compose：

```bash
docker compose up -d
```

该命令只启动数据库，不启动应用。数据库绑定 `127.0.0.1:55432`，使用独立命名卷。现有 Compose 与配置示例提供了相匹配的本地演示密码，不能作为生产凭据。

自定义密码时，应同时更新 `.env.local` 中的 `PGPASSWORD`，并通过 shell 环境变量 `GEODESK_POSTGRES_PASSWORD` 向 Compose 提供相同值。Compose 不会自动读取 `.env.local`；已有数据库卷的密码也不会因修改变量而自动改变。

不使用 Docker 时，将配置指向自行创建并确认隔离的 PostgreSQL 即可。

### 3. 迁移、检查与启动

确认目标不是生产数据库后执行：

```bash
npm run migrate:db
npm run check:db
npm run dev
```

迁移会修改数据库结构；`check:db` 会检查连接和已有结构，因此首次运行应先迁移再检查。数据库名称校验不能替代人工确认目标环境。

| 服务 | 地址 |
| --- | --- |
| Web | http://127.0.0.1:5173 |
| API | http://127.0.0.1:8787 |

按 `Ctrl+C` 停止应用。使用 Compose 时，可运行 `docker compose stop` 停止数据库并保留数据。

## 架构与数据边界

```text
浏览器：React / TypeScript / Vite
    │ 同源 /api 代理
本地 Node.js HTTP API
    ├── PostgreSQL：项目、问题、诊断回答、文章、检查结果和任务状态
    ├── 豆包：服务端模型调用
    └── 网站读取：技术与内容检查
```

浏览器不直接连接数据库，也不持有模型 API Key。真实模式会保存原始诊断回答和引用证据；不要将这些业务数据或数据库备份提交到公开仓库。网站读取和模型调用可能处理项目中填写的业务信息，使用前应评估供应商、地区及数据合规要求。

模型账号、调用额度、数据库和网络服务由使用者自行配置并承担费用。Codex for Open Source 如提供支持，其用途是项目研发和维护，不意味着代付 GEO 监测模型费用。

更多说明见 [架构文档](docs/architecture.md) 和 [业务规则](docs/business-rules.md)。

## 开发与验证

在安装依赖后运行：

```bash
npm test
npm run build
npm run smoke:demo
```

- `test`：单元、边界和接口契约测试，不证明真实模型输出质量。
- `build`：TypeScript 检查和前端构建，不是完整生产部署。
- `smoke:demo`：自动验证合成演示流程；运行前请确保演示端口没有被其他任务占用。
- `preview`：仅预览前端构建产物，不会启动真实 API。

发布前还应运行依赖审计，并在**清洁交付副本**中执行公开内容扫描：

```bash
npm audit
npm run check:public
```

`check:public` 检查实际文件树，不仅检查 Git 忽略规则；含 `node_modules`、`dist`、`.env.local` 或 `.git` 的开发目录会被报告。不要为了通过检查删除正在使用的配置或仓库历史，应准备单独的清洁副本。未安装 gitleaks 时，脚本仅执行自定义扫描，不代表完整历史凭据审计。

### 当前验证限制

- 上一次本地依赖审计仍有中危与高危告警，涉及 `sanitize-html` 和 `undici`；本文档更新不包含修复，正式发布前应升级、回归并重新审计。
- 独立 PostgreSQL 的实际迁移验收尚未完成；现有单元测试与演示不能替代该验收。
- 本地 Host/Origin 校验不能替代生产级身份认证与授权。

详见 [测试说明](docs/testing.md) 和 [发布清单](docs/release-checklist.md)。
