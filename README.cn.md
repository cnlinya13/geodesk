# GEODesk

中文 | [English](README.md)

**AI 搜索时代，你的网站在 AI 的回答里长什么样？**

用户不再点开 10 个蓝色链接，而是直接问 AI 要答案。你的网站在 AI 的回答中是被推荐、被引用，还是根本不存在——GEODesk 就是帮你回答这个问题的监测与诊断工作区，当前聚焦中文网站。

## 一个例子

你是某旅行网站的运营，想知道：当用户问豆包"大连亲子游推荐"时，你的网站会不会出现。GEODesk 用 20 道固定题去问模型，告诉你：10 个推荐类问题里你的网站被提到 2 次，官网链接一次也没被引用；诊断报告指出你的攻略页缺的是可被引用的结构化信息；你按写作任务补了 3 篇文章并发布；下一轮监测，推荐率从 20% 升到 50%。这就是 GEODesk 的完整一圈。

## 它解决什么问题

- **看见 AI 眼中的自己**：真实模型按固定题库作答，每题的原始回答、引用链接、模型信息全部留存，算出推荐率与官网引用率——不再靠猜。
- **让优化效果可衡量**：监测按轮次进行，一键"对比上一轮"，只看结构化变化（推荐翻转、引用翻转、链接增减），改版有没有用，数据说了算。
- **从发现问题到动手改**：诊断报告定位问题，技术审计与内容审计给出证据，写作任务产出优化内容，站外发布后手动回来确认。
- **开箱即用，也方便二次开发**：模型走 `ModelAdapter` 插件接入（豆包为首个实现），数据库走 `DbAdapter` 接口（内置 SQLite，PostgreSQL / MySQL / MariaDB 已验证可插拔）。

## 和传统 SEO 工具的区别

| | 传统 SEO 工具 | GEODesk |
|---|---|---|
| 监测对象 | 搜索引擎结果排名 | AI 回答中的推荐与引用 |
| 拿到的数据 | 排名位置、预估流量 | 模型原始回答、引用链接、推荐率 |
| 优化动作 | 关键词、外链 | 诊断 → 写作任务 → 轮次对比验证 |

## 快速体验（无需模型 key）

```bash
curl -fsSL https://raw.githubusercontent.com/cnlinya13/geodesk/main/deploy.sh | sudo bash
```

一条命令完成部署（Node 安装、前端构建、systemd 服务、nginx 反向代理），默认 IP 访问、可选绑定域名自动配 HTTPS。演示站用合成数据，不请求真实网站与模型，重启后重置。

本地体验：`npm ci && npm run demo`，打开 http://127.0.0.1:5174。

## 功能一览

| 阶段 | 能力 |
|---|---|
| 立项与题库 | 管理网站与优化目标；20 道固定题（10 推荐 / 6 筛选 / 4 决策），锁定后不可篡改 |
| 初始诊断 | 逐题存原始回答、引用链接、模型信息；推荐率 / 官网引用率分别统计；诊断报告 + PDF 导出 |
| 网站检查 | 技术审计（非 AI）与内容审计（模型辅助）分离，问题与证据分别留存 |
| 优化任务 | 生成写作任务与文章正文，站外发布后手动回确认 |
| 持续监测 | 相同题库发起新轮次，成对比较看变化 |

## 技术

React + TypeScript + Vite 前端；Node 24 原生 `node:http` 服务；SQLite 内置数据库（零依赖，文件即数据库）；模型与数据库双适配器可插拔。

## 当前状态

本地单用户 MVP：账号体系（admin / 普通用户）、豆包为首个真实模型、合成演示站免登录开箱即用。

> 不承诺提升搜索排名、推荐率或引用率。当前 API 请勿直接暴露到公网。
